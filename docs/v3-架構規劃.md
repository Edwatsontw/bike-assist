# bike-assist v3 架構規劃

> 建立日期：2026-07-20
> 定位：**v3 是「架構版本」，不是硬體版本**。
> v1→v2 換了主板（腳位大改版）；v2→v3 硬體完全不動，
> 進化的是系統架構：從「單機獨立運作」→「車＋站點＋雲三層系統」。

---

## 一、版本演進定位

| 版本 | 核心 | 硬體 | 網路 |
|---|---|---|---|
| v1 | 初代原型 | 初代板 | — |
| v2 | 單機完整功能（煞車/碰撞警示、搖桿方向燈、行車紀錄、GPS） | GOOUUU ESP32-S3-CAM | 獨立運作，WiFi 僅手機直連看串流 |
| **v3** | **車＋站點＋雲：影像回傳、伺服器辨識、地圖標記** | **沿用 v2 不動** | 歸還站 WiFi 批次上傳 → 24hr 家用伺服器 |

## 二、三層架構

```
車上（v2 硬體沿用）          歸還站點                 家用伺服器（24hr）
┌──────────────────┐  ┌────────────────┐  ┌───────────────────────────┐
│ 騎乘中：拍照存 SD  │→│ 服務機 WiFi     │→│ FastAPI（現有 server/ 擴充）│
│ 附 GPS＋時間戳     │  │ 收整趟批次資料   │  │ ① YOLO11n GPU 推論標記     │
│ 煞車/碰撞警示照常  │  │ 轉送雲端伺服器   │  │ ② 地圖：路線＋標記位置統計  │
└──────────────────┘  └────────────────┘  └───────────────────────────┘
```

- **偵測類別**：pothole（沿用現有資料）＋ 流浪狗（公開資料集，新類別）
- **不需要車上即時反應**：警示功能已由 AccelAnalyzer（IMU）在 v2 完成

## 三、伺服器（v3 核心新建部分）

- **硬體**：使用者家中電腦 24 小時開機（RTX 5070——訓練與推論同機，
  模型不需搬移／轉換部署格式）
- **對外連線**：不透過熱點。站點服務機經網際網路把資料傳到家用伺服器。
  連線方案待選（下一步決策）：
  - **Cloudflare Tunnel（建議先評估）**：免公網 IP、免路由器 port forwarding、
    免費、自帶 HTTPS；家用網路最少設定
  - DDNS + port forwarding：傳統做法，需路由器可設定、暴露家用 IP
  - （已有 `remote-wake-tool` 遠端開機子專案經驗可借用於維運）
- **軟體**：擴充現有 `server/`（FastAPI）：
  1. 批次上傳 API（影像＋log.csv metadata）
  2. YOLO11n 推論（pothole/dog）→ 標記照片存檔
  3. 地圖服務（Leaflet + OpenStreetMap，免費無金鑰）

## 四、識別迭代閉環——分兩階段（使用者定義）

**階段 1：預訓練模型自動分類標記**
- 用已訓練的 YOLO11n（重訓為 pothole+dog 2 類後）對回傳影像自動推論
- 有偵測到 → 該照片標記（類別、bbox、信心值）並歸檔

**階段 2：地圖統計**
- 依每張照片的 GPS 座標，在伺服器地圖上：
  - **統計路線**（整趟 GPS 軌跡描繪）
  - **標記標籤位置**（坑洞點位圖／流浪狗出沒點位圖，可分類篩選）

（真實影像回流再訓練屬於此閉環的自然延伸，待階段 1、2 跑通後評估。）

## 五、v3 待辦總表（優先序）

1. 韌體：`/dashcam/log.csv` 補 GPS 座標＋時間戳（地圖標記前提；資料韌體都有，
   只是沒寫進 log，改動小）
2. ML：流浪狗公開資料集下載合併 → 2 類 `data.yaml` → YOLO11n 重訓
3. 伺服器：批次上傳 API ＋ YOLO11n 推論標記（階段 1）
4. 伺服器：地圖路線＋標記統計（階段 2，Leaflet+OSM）
5. 伺服器：對外連線方案定案與架設（Cloudflare Tunnel vs DDNS）＋ 24hr 維運
6. 韌體：站點 WiFi 批次上傳模式（`NetworkManager` 重啟改造）
7. 站點服務機（可先用任何一台電腦/開發機扮演，驗證流程；正式服務機硬體
   選型可留 v3 後期或 v4）
8. 端到端測試：騎乘 → 歸還上傳 → 自動標記 → 地圖呈現

## 六、範圍外（明確不做）

- 車上硬體改動（板子、感測器、PCB 均沿用 v2）
- 車上 on-device AI 推論（espdet_pico/ESP-IDF 線已擱置，成果存檔備查）
- 車上即時偵測反應（警示已由 IMU 方案滿足）
- 正式站點服務機硬體選型（先用現有電腦扮演）

## 七、專案組織建議

硬體不動、韌體大部分沿用、主要新增在伺服器端——建議**同一專案內演進**
（不開新資料夾），以本文件與 git 歷史作為 v2→v3 的分界標記。
若之後要打 git tag，可在 log.csv 改版（待辦 1）合併時打 `v3-start`。
